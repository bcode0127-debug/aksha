# ADR-015: ESA-ADB Mission2 supersedes OPSSAT-AD as the build dataset

Status: Accepted. Supersedes ADR-006.

Context: ADR-006 locked OPSSAT-AD (18.5 MB, published 1594/529 split, 18 features) over the full ESA-ADB suite (11.6 GB across three missions) for cost reasons. On Aug 14, after inspecting ESA-ADB directly (Kotowski et al., "European Space Agency Benchmark for Anomaly Detection in Satellite Telemetry," arXiv:2406.17826, Tables 1-2), we found the missions are not interchangeable: Mission1's classical detectors -- PCC, HBOS, IForest, KNN -- all score event-wise F0.5 < 0.001 (both the lightweight 41-46 subset and the full channel set), making it unusable as a build target; Mission3 is excluded from ESA-ADB by the paper's own authors, "because of a small number and triviality of anomalies... and a large number of communication gaps and invalid segments" (§"ESA Anomalies Dataset"); and Mission2's lightweight channel subset (channels 18-28) is viable -- IForest 0.609 F0.5, Windowed IForest 0.949 F0.5, event-wise (Table 2) -- with real telecommand context (123 telecommands, 1,918,002 executions, Table 1) and 613 labeled rare nominal events (Table 1) that OPSSAT-AD's flat 18-feature vector cannot provide. We pivoted the build to Mission2.

Decision: Build against ESA-ADB Mission2's lightweight channel subset (channels 18-28), not OPSSAT-AD.

Consequences: No anomaly-class detection metric on the OPSSAT-AD 30-baseline comparison ADR-012 assumed -- that comparison no longer applies, since the detector runs on a different feature vector (22 features, not OPSSAT-AD's 18) against a different benchmark entirely. Mission2 test-split positives are evaluated as `rare_event ∪ anomaly` (ESA-ADB's own pooling convention -- Table 2's caption: "detection of all events excluding communication gaps"), because Mission2's test split carries only 4 true anomaly-labelled windows from a single event, too few to support a headline anomaly-only metric on its own. Telecommand-aware features and the gate/calibration pipeline (nearest rare-event-exemplar distance) became possible, which OPSSAT-AD's flat feature table did not support. OPSSAT-AD is retained only as a citation for the operator-requirements framing -- ADR-006's original secondary role for it -- not as build data.
