# ADR-013: Orchestration is an ADK 2 graph workflow (Pillar 1)

Status: **Accepted**.

Context: ADK 2's three orchestration patterns are distinguished by who picks the next step: the drawn graph, the LLM, or runtime code (ADK 2 codelab, Q. Wang, Aug 3 2026). Its design rule: predictable work stays as functions, clear rules become explicit routing, reasoning uses the model. Step 0 of its decision tree prefers prebuilt SequentialAgent/ParallelAgent/LoopAgent unless you need explicit routing, a join, or non-agent nodes.

Decision: `Workflow(edges=...)` on `google-adk==2.3.0` (tutorial-verified pin; re-verify on any bump, 2.x is not one behavior surface). Function nodes: detect, assemble_explainer_input, file_report. Agent nodes: investigate and explain, `mode="single_turn"`, every boundary validated by `input_schema`. Dict-edge routers for the gate verdict and severity, both carrying DEFAULT_ROUTE to the log tier with the incident flagged. Two LLM calls per incident, total.

ADR-005 enforcement: `assemble_explainer_input` (0 LLM) builds the explainer's input as DetectionResult + evidence + hypothesis and drops investigator_confidence. Isolation is an edge in the graph, visible in `Workflow.graph.edges`.

Rejected: prebuilt SequentialAgent — fails the codelab's own step 0 on both named grounds for us, deterministic steps would become model calls and routing would hide in prompts. Pillar 2 (collaborative) — LLM-decided control flow contradicts a deterministic triage guarantee, and there is no human conversation. Pillar 3 (dynamic) — our shape never varies at runtime.

Consequences: the architecture diagram is generated from `graph.edges` by our own small script, so the scored diagram is provably the running system. Node names become part of the routing contract. Cost floor is the two reasoning calls.

Verified: ADK 2 spike, `google-adk==2.3.0`, AI Studio key, Aug 13 2026. Three deliberate node failures against the tutorial's `L2b_router` workflow:
- An unhandled exception raised inside a function node propagates unwrapped (original exception type and traceback intact) up through the workflow runner to the caller. Exit code 1. Downstream nodes never run — a failed parallel-join predecessor prevents the join from completing.
- An agent node's `input_schema` validation fires at the node's input gate, before any LLM call is made. A `pydantic.ValidationError` there means the model was never invoked — the failure is entirely upstream of the agent.
- A router emitting a route value with no matching key in the route dict does **not** raise. ADK logs one line ("has conditional/DEFAULT edges but none were matched") and the branch silently ends — exit code 0, no error, no output from that branch. This confirms DEFAULT_ROUTE (TRD §9) is load-bearing, not defensive boilerplate, and confirms ADK has a native DEFAULT-edge concept the dict-edge routers can use.
- `retry_config` is a per-node, opt-in setting (default `None` — nothing retries unless configured). When set: `max_attempts` (default 5), `initial_delay` (default 1s), `max_delay` (default 60s), `backoff_factor` (default 2.0), `jitter`, and an `exceptions` allowlist restricting which exception types retry. Per-node `timeout` is separate and raises `NodeTimeoutError`, which is retry-compatible.
- Callbacks/hooks in `google-adk` exist at the agent/model/tool/run level only (`before_model_callback`, `on_tool_error_callback`, etc.) — there is no node-level or workflow-graph-level hook.
