# ADR-011: Two-topic split-queue over single push chain

Status: Accepted

Context: a two-LLM chain inside one push subscription risks blowing the ack deadline and triggering redelivery mid-run; Pub/Sub push acks cap at 600s; exactly-once is pull-only (not needed, idempotency covers at-least-once); a pull subscriber would kill scale-to-zero. Decision: fast detector service acks in milliseconds and republishes; slow triage service on its own push subscription at the 600s ceiling; dead-letter both; idempotent workers. Flip threshold: per-incident LLM latency approaching 600s moves triage to pull with lease extension or Cloud Tasks. All figures per official GCP docs.
